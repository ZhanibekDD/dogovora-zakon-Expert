# ZakonExpert Bot

Telegram-бот для автоматического формирования юридических договоров ТОО «ZakonExpert» (БИН 260740044168, руководитель Кияшев Жанибек Даулетович). Бот принимает удостоверение личности либо ФИО и ИИН текстом, распознаёт условия услуги через OpenAI, формирует профессиональный DOCX/PDF и позволяет клиенту подписать договор простой электронной подписью через отдельную веб-страницу (FastAPI).

## 1. Назначение

Один универсальный сценарий, без анкет и переключения режимов:

- можно просто отправить фото/PDF удостоверения и дописать условия следующим сообщением;
- можно написать ФИО + ИИН текстом, без фото;
- можно передать ФИО, ИИН и все условия одним сообщением.

Готовый договор создаётся **сразу с подписью и печатью Исполнителя**, без отдельного шага «Утвердить».

- Распознавание ФИО, ИИН, даты рождения через OpenAI Vision (Structured Outputs) либо безопасный текстовый ввод ФИО + ИИН; условия услуги извлекаются параллельно.
- Уточняющий вопрос задаётся только когда данных действительно не хватает (стоимость, порядок оплаты, ФИО, ИИН, вид услуги) — одним компактным сообщением, без пошаговой анкеты.
- Готовый договор редактируется ответом (reply) на сообщение с ним обычным текстом — без отдельного меню правки; каждая правка перевыпускает документ с подписью/печатью заново.
- Постоянное меню внизу экрана (Reply-клавиатура) — «Новый договор», «Мои договоры», «Найти договор», «Шаблоны», «Помощь», «Настройки» (для admin/superadmin).
- Автонумерация договоров, дата по Asia/Almaty, заполнение DOCX, стабильная конвертация в PDF через изолированный профиль LibreOffice.
- Автоподготовка PNG подписи/печати: удаление белого/прозрачного поля, сохранение пропорций и печать в реалистичном физическом размере (по умолчанию подпись 37 мм, печать 38 мм).
- Отправка клиенту одноразовой ссылки на подписание (Canvas-подпись, простая электронная подпись).
- **Отдельная функция «📝 Сформировать возражение»** — отправьте фото/PDF исполнительной надписи нотариуса + телефон клиента в подписи, бот через OpenAI распознаёт реквизиты (нотариус, должник, взыскатель, суммы, номера) и формирует готовое возражение на исполнительную надпись по утверждённому шаблону. Доступна только конкретным Telegram-аккаунтам (`OBJECTION_ALLOWED_TELEGRAM_IDS`), не всем сотрудникам.
- Ролевой доступ (superadmin/admin/manager/client), полный аудит действий.

> **Открытый доступ.** По решению владельца бота проверка списка сотрудников отключена:
> любой пользователь Telegram, впервые написавший боту, автоматически получает роль
> `manager` (может создавать и вести договоры). Действия уровня `admin`/`superadmin`
> (утверждение договора, настройки, сотрудники, подпись/печать, резервные копии) по-прежнему
> ограничены — эти роли выдаются только вручную через `SUPERADMIN_TELEGRAM_IDS` или
> `/employees_add`. Заблокировать конкретного пользователя можно командой `/employees_block`.

## 1.1. Как это работает

Отправьте одним сообщением фотографию (или PDF) удостоверения личности клиента, указав в
подписи к файлу все известные условия обычным языком:

> «+7 702 242 4487, отмена ареста от ЧСИ, стоимость 20 000 тенге, оплата после результата»

Команда `/new_contract` не обязательна — если авторизованный сотрудник просто пришлёт фото/PDF
с подписью, где явно упомянута сумма или ключевые слова услуги (договор, арест, ЧСИ, нотариус,
исполнительная надпись, судебное решение, график, запрет на выезд, штраф, оплата сразу/после),
бот распознает это как запрос на договор автоматически, без команды.

Бот параллельно (одним запросом к OpenAI Vision + одним связанным текстовым запросом):
1. скачивает фото/PDF (для PDF — рендерит первую и, при необходимости, вторую страницу в PNG для распознавания обеих сторон удостоверения);
2. распознаёт ФИО, ИИН, дату рождения;
3. извлекает из подписи телефон, услугу, стоимость, порядок оплаты, срок, результат, а также
   упомянутые банк/взыскателя/нотариуса/ЧСИ/номер исполнительного производства;
4. подбирает утверждённый шаблон и формулировку результата, затем через отдельный запрос к
   OpenAI переписывает пункты 1.1 «Предмет договора» и 1.2 «В состав услуг входят» под
   конкретный случай — вплетая в утверждённую формулировку названные банк/взыскателя/ЧСИ/номер
   дела, чтобы договор читался как составленный именно под этого клиента, а не как обезличенный
   шаблон. Юридический смысл, структура обязательств и остальной текст договора при этом не
   меняются ни на слово — GPT только заполняет формулировку конкретикой и не может ничего
   выдумать: при отсутствии специфики или недоступности OpenAI пункты остаются в исходном
   утверждённом виде;
5. присваивает следующий номер договора, ставит дату по Asia/Almaty;
6. **сразу формирует итоговые DOCX и PDF с вставленными подписью и печатью Исполнителя** (без
   отдельного шага «Утвердить» и без водяного знака-черновика) и присылает оба файла с
   компактными кнопками: `✏️ Исправить` / `🔄 Переделать условия` / `📤 Отправить клиенту на
   подписание` / `🗑 Отменить договор`.

> ⚠️ Подпись и печать ставятся автоматически, без отдельной проверки администратором перед
> подписанием печатью, — это осознанный выбор в пользу скорости. Если что-то распознано
> неверно, поправьте это ответом на сообщение с договором (см. ниже) до отправки клиенту на
> подписание.

Если критических данных не хватает (стоимость, порядок оплаты, ФИО, ИИН или вид услуги — но
**не** дата рождения, адрес, номер или срок действия удостоверения), бот задаёт один компактный
вопрос:

> «Не хватает данных для договора:
> 1. Стоимость услуги
> 2. Оплата сразу или после результата?
>
> Ответьте одним сообщением, например: "50 000 тенге, оплата после результата".»

После ответа договор достраивается без повторной загрузки удостоверения. Если уверенность в
распознанных ФИО/ИИН низкая, договор всё равно формируется (уже с подписью/печатью), но сверху
добавляется пометка «⚠️ Проверьте ФИО и ИИН перед утверждением» — стоит свериться с оригиналом
удостоверения и при необходимости поправить данные ответом на сообщение.

**Правка готового договора** — ответьте (reply) на сообщение с договором обычным текстом:

> «Поменяй стоимость на 30 000» · «Оплата не сразу, а после результата» · «Убери адрес» ·
> «Номер клиента +7 777 000 0000» · «Срок сопровождения 2 года» · «Добавь отмену исполнительной надписи»

Бот определяет договор по тому, на какое сообщение вы ответили, меняет только упомянутые поля,
создаёт новую версию DOCX/PDF (снова с подписью/печатью) и присылает обновлённые файлы. Договор,
уже отправленный клиенту на подписание или подписанный им, так изменить нельзя — бот ответит
отказом, чтобы клиент не подписывал не тот текст, что ему показали.

## 1.2. «Сформировать возражение» — как это работает

Отдельная функция, не связанная с договорами: формирование возражения на исполнительную
надпись нотариуса. Доступна только тем, чей Telegram ID перечислен в
`OBJECTION_ALLOWED_TELEGRAM_IDS` — остальные сотрудники даже не увидят кнопку в меню.

1. `/objection` или кнопка «📝 Сформировать возражение» → бот просит прислать фото/PDF
   исполнительной надписи (документ портала «Е-Нотариат») с телефоном клиента в подписи.
2. Бот распознаёт через OpenAI Vision: нотариуса (город, ФИО, лицензия), должника (ФИО, ИИН,
   дата рождения, адрес), взыскателя (наименование, БИН — сразу в родительном падеже для
   вставки после «в пользу»), суммы, уникальный номер и номер в реестре, а также основание
   взыскания (номер и дата договора), если оно читается.
3. Пол должника (для правильного «не согласна»/«не согласен», «подписывала»/«подписывал» и
   т.д. по всему тексту) определяется по контрольной цифре ИИН — никогда не угадывается по
   фамилии.
4. Если критических данных не хватает (ИИН, ФИО, номера, взыскатель, сумма, телефон клиента)
   — бот задаёт один компактный уточняющий вопрос, как и в основном сценарии.
5. Готовое возражение (DOCX + PDF) формируется по утверждённому шаблону ZakonExpert
   и присылается сотруднику под понятным именем файла.

Эта функция ничего не пишет в базу данных договоров — это самостоятельный инструмент
формирования документа, без хранения истории обращений.


## 3. Установка на Windows 11

```powershell
py -3.12 -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
copy .env.example .env    # заполните значения, см. раздел 7
```

Для реальной конвертации DOCX→PDF локально на Windows установите LibreOffice (https://www.libreoffice.org/), затем укажите путь в `.env`:
```
LIBREOFFICE_PATH=C:\Program Files\LibreOffice\program\soffice.exe
```
Локально также нужны PostgreSQL и Redis (можно поднять их только через Docker, см. раздел 5, а бота/API запускать локально из venv).

## 4. Установка на Ubuntu 24.04

```bash
sudo apt update && sudo apt install -y python3.12-venv libreoffice-writer fonts-liberation2 postgresql redis-server
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

```

## 5. Запуск через Docker Compose

```bash
cp .env.example .env   # заполните значения
docker compose up -d --build
docker compose logs -f bot
```

Сервисы: `postgres`, `redis`, `migrate` (одноразовые миграции Alembic), `bot`, `api` (страница подписания, порт 8000), `worker` (очередь конвертации PDF). Все данные (`storage/`) хранятся в именованном volume `storage_data`.

## 6. Создание Telegram-бота через BotFather

1. Откройте `@BotFather` в Telegram → `/newbot` → задайте имя и username.
2. Скопируйте токен в `TELEGRAM_BOT_TOKEN` в `.env`.

⚠️ Токен, который был передан в этом чате, следует считать скомпрометированным (он прошёл через текстовый диалог) — пересоздайте его через `@BotFather` → `/revoke` перед боевым запуском.

## 7. Получение Telegram ID администратора

Напишите `@userinfobot` в Telegram — он пришлёт ваш числовой ID. Добавьте его в `.env`:
```
SUPERADMIN_TELEGRAM_IDS=123456789,987654321
```
При старте бота (`ensure_superadmins` в `app/bot/main.py`) все перечисленные ID автоматически получают роль `superadmin` и активную запись сотрудника — это единственный способ не оказаться без доступа к собственному боту.

## 7.1. Ограничение доступа к «Сформировать возражение»

Функция формирования возражений — не часть общего доступа для сотрудников. Она видна и доступна только тем Telegram ID, которые перечислены в `.env`:
```
OBJECTION_ALLOWED_TELEGRAM_IDS=123456789
EXECUTOR_EMAIL=
```
`OBJECTION_ALLOWED_TELEGRAM_IDS` — список ID через запятую (тот же формат, что `SUPERADMIN_TELEGRAM_IDS`); у остальных сотрудников кнопка «📝 Сформировать возражение» вообще не появляется в меню, а прямой вызов `/objection` отклоняется с сообщением о недоступности. `EXECUTOR_EMAIL` — необязательный запасной email, который подставляется в текст возражения, если клиент не указал свой в подписи к документу.

## 8. Настройка OpenAI API

```
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4.1   # любая модель с поддержкой vision + Structured Outputs
```
⚠️ Ключ, переданный в этом чате, также считайте скомпрометированным — пересоздайте его в https://platform.openai.com/api-keys.

Если `OPENAI_API_KEY` пуст, бот автоматически переходит в ручной режим: сотрудник вводит все поля вручную, распознавание не выполняется (без падения сервиса).

## 9. Загрузка подписи и печати Исполнителя

1. От имени супер-администратора отправьте боту `/signature_settings`.
2. Пришлите PNG подписи с прозрачным фоном **как документ** (не как фото).
3. Пришлите PNG печати с прозрачным фоном.

Файлы сохраняются в `app/templates/assets/signature/` (вне публичного доступа, права ограничены), для каждого считается SHA-256 и сохраняется привязка к действующим БИН/ИИН Исполнителя (`app/templates/assets/signature/hashes.json`). Если реквизиты организации изменились, файл был заменён вручную либо привязка отсутствует, выпуск финального договора блокируется до повторной загрузки обоих PNG через `/signature_settings`. Сами изображения никогда не попадают в логи и не отправляются пользователям отдельными файлами — только внутри итогового PDF после утверждения договора.

Реальные файлы подписи и печати намеренно не хранятся в Git. Загрузите их один раз через `/signature_settings`: бот проверит PNG, автоматически обрежет пустые поля и приведёт изображения к стабильной геометрии. Значения `EXECUTOR_SIGNATURE_WIDTH_MM` и `EXECUTOR_STAMP_DIAMETER_MM` управляют физическим размером в договоре.

## 10. Добавление DOCX-шаблонов

Мастер-шаблон (`app/templates/contracts/master_v1.docx`) построен для ТОО «ZakonExpert» на A4 с фиксированной геометрией таблиц, отдельной страницей реквизитов и устойчивым блоком подписей. 11 типов договоров (`app/core/constants.py::TEMPLATE_CODES`) используют один утверждённый DOCX-скелет; базовый предмет/действия/результат задаются пресетами в `app/services/template_service.py`, а пункты 1.1/1.2 дополнительно переписываются под конкретный случай через `openai_service.draft_contract_narrative`. Остальной юридический текст шаблона не проходит через GPT.

Чтобы изменить юридический текст шаблона:
```bash
# отредактируйте scripts/build_master_template.py, затем:
python scripts/build_master_template.py
```
Это создаст новую версию `master_v1.docx`. Для полноценного версионирования — сохраните файл под новым именем (`master_v2.docx`) и заведите новую запись `ContractTemplate` с `version=2`.

## 11. Добавление нового сотрудника

Доступ открыт: любой, кто напишет боту `/start`, автоматически регистрируется с ролью `manager` и сразу может создавать договоры — отдельно добавлять его не нужно.

`/employees_add <telegram_id> <ФИО>` по-прежнему полезен, чтобы заранее завести запись с читаемым ФИО до того, как человек сам напишет боту. Чтобы выдать роль `admin`/`superadmin` (доступ к утверждению договоров, настройкам, подписи/печати, бэкапам), пропишите Telegram ID в `SUPERADMIN_TELEGRAM_IDS` и перезапустите бота, либо вручную обновите `role_id` в таблице `users`.

Заблокировать доступ конкретному человеку:
```
/employees_block <telegram_id>
```
Список сотрудников: `/employees`.

## 12. Создание первого договора

1. `/start` → «📄 Новый договор» (или сразу `/new_contract`, или просто пришлите фото).
2. Отправьте фото/PDF удостоверения либо текст:
   `ФИО: Иванов Иван Иванович, ИИН: 900101300123; снятие ареста; 50000 тенге; оплата после результата; +7 700 000 00 00`
3. Бот сразу присылает готовый **итоговый** DOCX+PDF — с уже вставленными подписью и печатью
   Исполнителя, без водяного знака и без отдельного шага «Утвердить» — с кнопками
   `✏️ Исправить` / `🔄 Переделать условия` / `📤 Отправить клиенту на подписание` / `🗑 Отменить
   договор`. Если чего-то критического не хватает — бот задаст один компактный уточняющий вопрос.
4. «📤 Отправить клиенту на подписание» → бот выдаёт одноразовую ссылку (24 часа) на страницу подписания (`APP_BASE_URL/sign/<id>?token=...`).
5. Клиент открывает ссылку, соглашается с условиями, рисует подпись на Canvas, нажимает «Подписать» → бот получает подписанный PDF с зафиксированными датой, IP, User-Agent и хешами документов.

Нужно поправить что-то в уже присланном договоре? Ответьте на сообщение с ним текстом
(«Поменяй стоимость на 30000») — см. раздел 1.1. Изменить или отменить можно вплоть до отправки
клиенту на подписание.

## 12.1. Формирование возражения на исполнительную надпись

Доступно только ID из `OBJECTION_ALLOWED_TELEGRAM_IDS` (см. раздел 7.1).

1. `/objection` или кнопка «📝 Сформировать возражение».
2. Пришлите фото/PDF исполнительной надписи нотариуса (документ портала «Е-Нотариат»), указав в
   подписи телефон клиента (и, при желании, email).
3. Бот распознаёт реквизиты через OpenAI Vision и сразу присылает готовые DOCX+PDF возражения по
   утверждённому шаблону. Если критических данных не хватает — задаёт один уточняющий вопрос
   (ответьте на его сообщение текстом).

Эта функция не пишет ничего в базу данных договоров — см. раздел 1.2.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Бот не отвечает на `/start` | Неверный `TELEGRAM_BOT_TOKEN` | Проверьте токен в `.env`, пересоздайте через BotFather |
| «⛔ Ваш доступ заблокирован» | Пользователь заблокирован через `/employees_block` | Разблокировать может только супер-администратор (правка записи `employees.is_blocked` в БД или будущая команда разблокировки) |
| «⛔ Доступно только администраторам/супер-администратору» | Настройки/сотрудники/подпись/бэкап — команды уровня admin+, обычный `manager` их не видит | Выдайте роль через `SUPERADMIN_TELEGRAM_IDS` (перезапуск) или `/employees_add` + ручное повышение роли в БД |
| Распознавание не работает, сразу ручной режим | `OPENAI_API_KEY` пуст или недействителен | Заполните ключ, проверьте квоту/лимиты на platform.openai.com |
| Ошибка конвертации PDF | LibreOffice не установлен / `LIBREOFFICE_PATH` неверен | Установите LibreOffice, укажите правильный путь к `soffice`/`soffice.exe` |
| «Задача конвертации PDF... таймаут» | RQ worker не запущен | `docker compose up worker` или `python -m app.worker` локально (с запущенным Redis) |
| Ссылка на подписание не открывается | Истёк срок токена (24 часа) или уже использована | Создайте новую ссылку через «Отправить клиенту на подписание» |
| Ошибка `pg_dump`/`psql` в backup/restore | Нет клиентских утилит PostgreSQL в PATH | Установите `postgresql-client` (Linux) / PostgreSQL client tools (Windows) |

## Настройки создания договора

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `QUICK_MODE_REQUIRE_PHONE` | `false` | Если `true`, отсутствие телефона клиента в подписи тоже считается недостающим полем и бот задаст уточняющий вопрос вместо создания договора с пустым телефоном. |
| `RELEASE_CONTRACT_NUMBER_ON_DELETE` | `false` | Если `true`, при отмене договора через «🗑 Отменить договор» номер освобождается — но **только** если это самый последний выданный номер (иначе освобождение создало бы дубль/пропуск, и бот молча оставит номер использованным). По умолчанию номера никогда не освобождаются. |

## Известные ограничения

- Изменение реквизитов Исполнителя (адрес, телефон, Kaspi и т.д.), кроме нумерации договоров, выполняется через `.env` + перезапуск, а не через диалог в боте — динамическое хранилище настроек в БД (`settings`) для этого создано, но UI редактирования в боте не реализован (только счётчик договоров редактируется через `/settings`).
- Тест конкурентной нумерации на реальном PostgreSQL (`tests/test_contract_numbering_postgres.py`) поднимает временный Docker-контейнер и пропускается автоматически, если демон Docker недоступен.
- Тесты, создающие реальный DOCX→PDF (включая создание и правку договора), пропускаются автоматически, если `soffice` не установлен локально.
- Уточняющий вопрос и связка «сообщение → договор» для правки ответом хранятся в Redis: черновик, ожидающий уточнения, живёт 30 минут; связка для правки — 60 дней. По истечении бот попросит начать заново.
- Автоопределение запроса на договор по фото без команды смотрит только на подпись к файлу (ключевые слова и наличие суммы); фото без подписи или с подписью без этих признаков нужно отправлять через `/new_contract`.
- «Сформировать возражение» — самостоятельный инструмент генерации документа, не связанный с договорами: результат не сохраняется в БД и не привязан к клиенту/сделке, история обращений не ведётся.
